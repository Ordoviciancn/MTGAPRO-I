# Forge 自动对局与竞技场交互 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 如需委派，可使用 superpowers:subagent-driven-development；不得将子任务报告代替主线程验收。

**Goal:** 在现有双人网页牌桌中提供由 Forge 裁定的完整对局，以自动时点确认减少无意义点击，并依据用户录屏逐项复现 MTGA 的操作反馈。

**Architecture:** Java Forge 进程持有规则状态，Node 管理房间、身份、命令和按座位脱敏的视图，React 呈现合法操作、待选问题和事件动画。手动房间与 Forge 房间分别处理命令。动画只消费引擎事件，不决定费用、伤害或结算。

**Tech Stack:** 现有 React 19、TypeScript、Vite、Express、WebSocket；Java 17、Maven 3.9.16；固定 Forge 提交 `c86308451651af63c1b4a69a2c47f9cd478d53f6`。

| `src/client/ArenaEffects.tsx`、`useRoomEffects.ts` | 动画呈现与队列生命周期 |

现有草案采用 stdout `FORGE_BRIDGE ` 前缀加 JSON、stdin 单行 JSON。任务 1 冻结协议版本；以下为目标接口，不表示现有 Java 文件已完全符合。

```ts
type Decision = {
  type: 'ok' | 'cancel' | 'selectCard' | 'selectPlayer' | 'choice';
  requestId: string; cardId?: number; playerId?: number;
  value?: number | number[];
};
type Command =
  | { type: 'init'; players: { name: string; deck: { name: string; count: number }[] }[] }
  | (Decision & { seat: 0 | 1 })
  | { type: 'control'; seat: 0 | 1; fullControl: boolean };
type Prompt = {
  seat: 0 | 1; requestId: string;
  kind: 'input' | 'choice' | 'unsupported'; message: string;
  options?: { value: number; label: string }[];
  min?: number; max?: number;
  okEnabled?: boolean; cancelEnabled?: boolean;
  okLabel?: string; cancelLabel?: string;
};
```

`requestId` 标识一个输入窗口；同一窗口的文字/按钮刷新不重新生成 ID，窗口结束后旧 ID 失效。`seat` 由 Node 根据连接填入。引擎仍须检查目标合法性与输入是否适用于当前窗口。任务 5 再扩充数值、排序和分配协议，不能把这些输入硬塞入单选索引。

## 4. 风险与决策原则

| 风险 | 对策与停线条件 |
| --- | --- |
| 人类控制器回调复杂，默认返回导致规则被跳过 | 逐个登记回调支持度；未知决策暂停，真人 smoke 不通过则不进入网页发布 |
| GUI/游戏线程相互等待 | 有界启动测试、线程诊断；输入答复不能排在正在等待自身答复的同一线程后 |
| 自动让过预测遗漏特殊动作 | 采用原生保守计算，保留完全操控和停点；收集明确卡牌回归，不宣称全覆盖 |
| 旧房间身份只是客户端 ID | 自动房间前补会话凭证；不允许跨座位决策或窃取待选问题 |
| 画面与规则状态不同步 | 规则立即确定，动画按事件呈现；重连直接落位，不重放费用与伤害 |
| 先重写 Unity 导致规则工作再度停滞 | 先完成 A/B；只有性能测量或明确资产需求支持时再做独立客户端计划 |
